# Мультиязычность (i18n) — плагин motorchk

**[Скачать](https://github.com/burzilov/motorchk-plugin-i18n/releases/latest)** — последний ZIP из GitHub Releases (распаковать в `public_html/plugins/`).

Языки сайта для motorchk 0.5.x (`"core": "^0.5"`): адреса `/en/…`, переводы Markdown-страниц, словарь строк
интерфейса, переключатель языка, `hreflang` и `<html lang>`.

Ядро 0.4 умеет показывать переводы страниц и выводить hreflang, но включает это только когда
есть служба `i18n` — её и даёт этот плагин. Без плагина сайт работает на одном языке, как раньше.

## Установка

```bash
./release.sh                     # тег v<версия> и dist/i18n-<версия>.zip из тега
```

`./release.sh` — релиз: проверяет чистое дерево и что первая запись CHANGELOG.md совпадает с version в plugin.json, ставит аннотированный тег `v<версия>` и собирает `dist/i18n-<версия>.zip` из тега (`git archive`). `./release.sh --push` — ещё и `git push` коммитов и тега в origin. Тег — точная ссылка на код развёрнутой версии: по нему видно, что стоит на сайте, и можно собрать тот же архив или сравнить версии (`git diff v0.1.0 v0.2.0`).

Распакуйте архив в `public_html/plugins/` (получится `plugins/i18n/`) и откройте в админке
**Языки**. При первой загрузке создаются `plugin-data/i18n/settings.json` (русский — основной,
английский) и `plugin-data/i18n/dictionary.json`.

Удаление: удалите `plugins/i18n/` — адреса `/en/…` перестанут работать (404), страницы на основном
языке не изменятся. Данные остаются в `plugin-data/i18n/`; файлы переводов `*.en.md` — в `content/`
(без плагина ядро считает их обычными страницами `/about.en`, см. «Ограничения»).

## Адреса

| Язык | Адрес |
|------|-------|
| основной (ru) | `/`, `/about`, `/customizer/razor/catcher` |
| дополнительный (en) | `/en/`, `/en/about`, `/en/customizer/razor/catcher` |

- `/ru/about` → 301 на `/about`, `/en` → 301 на `/en/`.
- Префикс работает для всех публичных адресов: Markdown-страниц и страниц плагинов. Админка, `/plugin-assets/…`, `/core/…`, `/api/…` префикс не получают.
- Страница со slug `en` (`content/en.md`) при включённом английском перекрывается префиксом.

## Как определяется язык

1. **Префикс адреса** (`/en/…`) — всегда главный. Без префикса — основной язык.
2. **Cookie `site_locale`** («Запоминать выбранный язык», включено): последний язык, на котором посетитель смотрел сайт. Используется **только на главной `/`**: с cookie `en` главная перенаправляет на `/en/`. Остальные адреса без префикса всегда открываются на основном языке — так ссылки на русские страницы остаются русскими.
3. **Accept-Language** (выключено по умолчанию): только при первом визите на главную (cookie ещё нет) — перенаправление на язык браузера. Осторожно: под него попадают и поисковые роботы.

`?lang=en` на любом адресе — явный выбор: cookie запоминает язык, затем 302 на чистый адрес
(`/about?lang=en` → `/en/about`). Ссылка переключателя на главную основного
языка — `/?lang=ru`, иначе запомненный английский снова перенаправил бы на `/en/`.

Посетителям, которые не переключали язык, cookie не ставится.

## Переводы страниц

Файл перевода лежит рядом с оригиналом, с кодом языка перед `.md`:

```text
content/about.md         → /about
content/about.en.md      → /en/about
content/index.en.md      → /en/
content/about/team.en.md → /en/about/team
```

- Формат — как у обычной страницы: front matter (`title`, `description`, `og_*`, `published`) и блоки. Адрес, шаблон и место в дереве — у оригинала.
- Нет перевода — по `/en/about` показывается оригинал с `<html lang="ru">` и `<link rel="canonical">` на `/about`; меню и переключатель — на английском.
- `hreflang` (и `x-default`) выводится только на страницах, у которых есть опубликованный перевод.
- Перевод показывается, только если оригинал опубликован. `published: false` в переводе — показывается оригинал.
- Переводы правятся файлами: редактора переводов в админке пока нет. Переименование страницы в админке файлы `*.en.md` не переносит.

Подробности ядра — `core/docs/11-i18n.md`.

## Переключатель

- **Плавающий** (по умолчанию): добавляется в конец каждой страницы, положение — в настройках.
- **Вручную**: `<!--i18n:switcher-->` в тексте Markdown-страницы или в шаблоне темы:

```php
<?= $i18n?->switcher() ?>
<?= $i18n?->switcher(['labels' => 'code', 'class' => 'ml-4']) ?>   <!-- RU / EN -->
```

Если на странице уже есть переключатель (вставка или шаблон), плавающий не добавляется. Стили —
`/plugin-assets/i18n/switcher.css` (классы `.i18n-switcher`, `.is-current`), подключаются на всех
страницах сайта.

## Словарь интерфейса

Строки для тем и плагинов: **Языки → Словарь**, ключ → значение на каждом языке.

```php
<?= htmlspecialchars($i18n?->t('footer.contacts', 'Контакты') ?? 'Контакты') ?>
```

`t()` ищет значение на текущем языке, затем на основном, затем возвращает запасной текст или ключ.

- Подписи меню на дополнительных языках: ключ `menu.{slug}` (`menu.about`) или ключ, равный подписи (`Главная`). Пункт без своей подписи берёт `title` перевода страницы.
- Подпись переключателя для экранных дикторов — ключ `i18n.switcher`.
- **Экспорт** — JSON-файл `{"format": "motorchk-i18n-dictionary", "version": 1, "locales": [...], "strings": {...}}`.
- **Импорт** — такой же файл или просто `{"ключ": {"ru": "…", "en": "…"}}`; «добавить» (значения из файла заменяют существующие) или «заменить целиком». Ошибочный файл не импортируется частично.
- В форме словаря есть предел PHP `max_input_vars` (обычно 1000 полей ≈ 300 ключей на 2 языка) — большие словари загружайте импортом.

## Служба для других плагинов

```php
$i18n = $plugin->service('i18n');            // null, если плагин не установлен
$i18n?->locale();                            // 'en'
$i18n?->t('cart.add', 'В корзину');
$i18n?->url('/customizer/razor', 'en');      // '/en/customizer/razor'
$i18n?->switcher();
```

Для языка и адресов достаточно API ядра — оно работает и без плагина: `$plugin->locale()`,
`$plugin->localized(['ru' => 'Ловушка', 'en' => 'Catcher'])` (текущий язык → основной → первое непустое; в теме —
`SiteLocale::localized([...])`), `$plugin->publicUrl('/x')` (с плагином — `/en/…`), опция
`renderPublic(..., ['alternates' => true])` для hreflang. Своего `localized()` у службы нет.

## Данные

| Файл | Что |
|------|-----|
| `plugin-data/i18n/settings.json` | языки, основной язык, определение языка, переключатель |
| `plugin-data/i18n/dictionary.json` | словарь `{"ключ": {"ru": "…", "en": "…"}}` |

Повреждённый файл (не JSON) плагин не перезаписывает: сайт работает с настройками по умолчанию
(или пустым словарём), в админке — предупреждение; файл меняется только явным сохранением или
импортом с заменой.

## Ограничения

- Переводы страниц — только файлами, без редактора в админке; inline-edit работает только на основном языке.
- Без плагина файлы `about.en.md` — обычные страницы ядра (`/about.en`). Если удаляете плагин, уберите или снимите с публикации переводы.
- Адреса страниц одинаковы на всех языках (`/en/about`, а не `/en/o-nas`→`/en/about-us`).
- Формы ядра (`/api/forms/submit`) отвечают на основном языке.
